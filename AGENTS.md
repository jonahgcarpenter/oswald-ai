# AGENTS.md — Oswald Developer Reference

Source, the operator-approved `internal/database/schema.sql`, and tests define implemented behavior. Keep this reference current when changing architecture, authorization, persistence, provider contracts, or operational limits.

## Change Discipline

- Do not edit `README.md` unless the user explicitly requests README changes. Update contributor documentation here instead.
- Preserve operator configuration, credentials, souls, memory, cache, databases, and unrelated working-tree changes. Never test against live credentials or a runtime database.
- Database changes require explicit user approval: tables, columns, indexes, triggers, constraints, versions, persisted JSON representations, field meanings, and moves between SQLite and filesystem persistence. Describe exact changes, data implications, and verification before implementation. Approval never authorizes deleting an operator database.
- Use the smallest correct cohesive change; group files by responsibility, not arbitrary size. Avoid generic utility packages and unnecessary service/interface layers.
- Use `gofmt`, standard-library/third-party/internal import groups, exported API doc comments, context-first cancelable APIs, wrapped causes, typed errors, and explicit failure/state transitions.
- Only `main` exits or logs fatal errors. Domain/startup APIs return errors after cleanup. Preserve resource ownership, rollback, row iteration checks, exact-token leases, delivery gates, and generation fences.
- Preserve external tool names, JSON fields, commands, routes, environment references, log keys, and persisted formats during internal refactors. Do not add compatibility APIs solely for obsolete fixtures.

## Build and Verification

This is a Go application, not a JavaScript/frontend project. The module declares Go 1.25.7. SQLite and image codecs need CGO and a C/C++ toolchain; use the `sqlite_fts5` build tag. Discord GIFV extraction needs `ffmpeg` and `ffprobe`.

```bash
go build -tags sqlite_fts5 ./...
go test -tags sqlite_fts5 ./...
go test -race -tags sqlite_fts5 ./...
go vet -tags sqlite_fts5 ./...
git diff --check
```

Use focused tests while editing and the full suite for cross-package changes. `GOTOOLCHAIN=go1.25.7` overrides a different installed toolchain. Tests use synthetic principals, temporary approved-schema databases/files, fake model clients/transports, local HTTP handlers, explicit clocks, and joined goroutines. They must not need secrets or live services. Startup tests inject clients/gateways rather than starting real listeners.

The release workflow runs tagged tests before publishing its container; it does not enforce every race/vet/formatting check on PRs.

## Architecture and Ownership

- `cmd/oswald`: operator CLI binary; parses argv, calls `internal/cli.Run`, and owns process exit.
- `cmd/oswald-server`: service binary; selects the root, delegates to `startup.Serve`, and owns process exit.
- `internal/cli`: operator command dispatch and exit-code mapping. Each command group is a subdirectory (`internal/cli/setup`, `internal/cli/start`, `internal/cli/profiles`). The server binaries never import this tree.
- `internal/startup`: sole composition root; profile agents, stores, providers, tools, workers, shared broker, gateways, ordered cleanup.
- `internal/config`: strict YAML, private profile environments, interpolation, retention, safe structured logging.
- `internal/profiles`: immutable trusted transport-to-profile routing; no account persistence or administration.
- `internal/identity`: dependency-light authenticated principal/resolver contracts. `CanonicalUserID` now carries the trusted profile name; retain this field and the `profile` log key for correlation contracts (the `user_id` detail is an untrusted display label, never ownership).
- `internal/agent`: iterative foreground loop; context, streaming, tools/history, image retries, request-local compaction in separate responsibility files.
- `internal/broker`: FIFO conversation lanes, profile fences, cancellation, bounded admission, global foreground priority.
- `internal/commands`: composition/adapters for `/help`, `/new`, `/stop` only.
- `internal/database`: exact approved-schema initialization and SQLite handle ownership; no migrations or account APIs.
- `internal/memory`: profile-local sessions, delivery/history/image metadata, compression receipts/campaigns, maintenance. `memory/files` owns immediate private file edits.
- `internal/compaction`: synchronous model compactor and durable profile worker. `compaction/budget` owns token estimates, capacity, pressure, tail policy; it depends on LLM contracts, not vice versa.
- `internal/gateway`: composition; concrete Discord/iMessage/OpenAI packages depend on `gateway/routing` and `gateway/runtime`, not their parent composition package.
- `internal/mcp`: lazy profile-configured bridge (`tool_search`/`tool_describe`/`tool_call`), schema projection, execution; no database/encryption configuration store. `oswald mcp auth` only authorizes; the service never starts interactive flows.
- `internal/media`: shared normalization/attachments; `media/imagecache` owns private cached images and expiry worker.
- `internal/soul`: read-only current profile policy with default-template fallback. Runtime never copies, migrates, edits, or deletes operator souls; only `oswald profile create` copies the root template into a new profile as its starting policy.
- `internal/tools`: builtin composition. Each group owns stable name, description, schema, handler/policy; `registry`, `exposure`, and `governance` remain independent. `tools/output` owns ANSI stripping and fixed-shape secret redaction for command output. Toolsets are code-owned bundles (`core`, `terminal`, `code_execution`, `cronjob`); gateways map to toolsets and the API intersects them with caller `named`/`allowed_tools` opt-in. Workspace `read_file` descriptions apply a per-request hosted-OCR override (`PDF (text layer)` -> `PDF (scanned or text)`) without mutating registry definitions.
- `internal/providers/web/{brave,searxng}` and `providers/image_generate/comfy_ui`: backend implementations, never import tool packages.
- `internal/process`: profile-scoped tracked background shell processes (`cache/processes/<id>/`, 0600/0700); completed retained 7d, newest 64/profile; `process_manage` companion (list/poll/log/wait/kill/write/submit/close/handoff, prefix match, handoff cap 3); global `StopAll` kills non-persistent entries before store close.
- `internal/cron`: per-profile scheduled jobs (`cron/jobs.json` + `executions.jsonl`, 0600/0700, atomic rewrites); schedule grammar (durations, `every` phrases, 5-field cron, RFC3339/`in` one-shots); validation (injection scan, script/context inside CWD, monitor xor, `no_agent` requires script, toolset allowlist, model/provider/base_url rejected as user-owned); `tick()` advances `next_run_at` before dispatch with `scheduled_instant` dedupe and half-period catch-up clamp (120s–2h); per-profile 30s sequential ticker joined before `StopAll`; `no_agent` empty output sends nothing; agent-mode runs record locally pending live-gateway delivery.
- `internal/shared/{requestctx,lease}`: narrow contracts; `shared` is directory grouping, not a utility facade.

Account/admin/bootstrap/link commands, moderation/ban hooks, principal refresh, account invalidation, API keys, migration machinery, legacy fact/formation stores, staging, derived-index workers, and transcript-search tooling are removed. No old database importer or automatic upgrade exists.

## Operator Profile Configuration

`.oswald/` is the default/global root. It owns `config.yaml`, private `.env`, `SOUL.md`, `memories/`, `.cache/images/`, `cache/scratch/`, and `state.db`. First install is seeded explicitly with `oswald setup`, which creates missing entries only (`0700` root and `profiles/`, `0600` `config.yaml`/`.env`/`SOUL.md`), enables the loopback API on the default profile, and never overwrites operator content; `oswald start` then runs the service. Named profiles live at `.oswald/profiles/<name>/` with the same profile-local resources and optional `config.yaml` overrides, and are provisioned explicitly with `oswald profile create <name>`. Create scaffolds the private directory (`.env`, minimal `config.yaml` limited to the four override keys, an initialized approved-schema `state.db`, and a copy of the root `SOUL.md`); it never overwrites an existing profile and rolls back partial state. `oswald profile delete <name>` refuses `default`, warns about dangling `profile_routes`, requires a plain `y`/`yes` confirmation, and removes only that subtree. The CLI never edits global configuration. Missing roots are not auto-created by the server. The complete supported configuration surface is defined in code as the `oswald setup` default; former application-setting environment variables are not a deployment interface.

Global YAML owns shared listeners, routes, admission policy, and inherited provider/model/tool/MCP defaults. Named YAML cannot override shared settings. Merge raw YAML before interpolation, then resolve each profile independently. A named profile inherits the default profile's `.env` values and overrides them with its own `profiles/<name>/.env`. Process variables, including explicitly empty values, take precedence. Loading never mutates the process environment.

Disabled platforms are pruned before interpolation, so a platform turned off never requires its credentials; unknown keys and unsupported platform names inside a disabled block are still rejected. Interpolation still happens for every other value in the document, so remove an absent credential reference (or give it a default) rather than relying on a feature being disabled.

Supported interpolation expressions: `${VAR}`, `${VAR:-default}`, `${VAR-default}`, `${VAR:?message}`/`${VAR?message}`, and `$$`. Bare missing variables fail safely with a classified configuration error. Loading never mutates the process environment.

Configuration failures surface as classified diagnostics. A failed load logs `error_code` with a fixed classification (for example `config_variable_missing`, `config_key_unknown`, `config_model_endpoint_invalid`, `config_platform_unsupported`, `config_dir_unavailable`) plus validated `config_path`, `config_source`, and `config_variable` fields naming the schema path, artifact, and referenced variable only. Configuration values and error text are never logged.

Config files are bounded to 256 KiB and reject symlinks, aliases, duplicate/unknown keys, and excessive nesting. Dotenv files must be private regular files. Profile names are bounded safe lowercase ASCII identifiers; `default` is reserved. Routes map transport-authenticated identities to existing profiles, normalize `bluebubbles` to internal `imessage`, and fall back to the default profile when no route matches. Explicit default routes need no multiplexing; named routes require it. Platform admission uses `allowed_users` (empty admits every routed identity) and `banned_users` (always rejected first, everywhere); admission is checked before attachment/reply work. Multiple configured identities can share one profile and its memory without linking accounts.

## SQLite State and Delivery

`database.OpenState` initializes an empty profile `state.db` transactionally with one version-1 `schema_version` row. It compares all schema objects, including generated ones, against the supplied baseline. SQL-token normalization ignores formatting/comments, not quoted literals. Existing incompatible/version-drifted/object-drifted databases, foreign-key violations, unsafe ancestors/files/sidecars, and pre-cancellation fail closed without rebuilding, deleting, or upgrading operator data.

The approved application tables are `schema_version`, `system_prompts`, `sessions`, `messages`, `session_model_usage`, `state_meta`, `gateway_routing`, `gateway_hygiene_state`, `conversation_generations`, `gateway_heartbeats`, `compression_locks`, `session_turn_leases`, and `async_delegations`. Keep the operator DDL unchanged unless separately approved.

`memory.ProfileStore` owns one trusted profile. Sessions use profile name, source, session key; `conversation_generations` preserves reset/expiry high-water fencing. Version-1 `sessions.origin_json` carries generation/TTL. Both user and assistant message rows remain inactive until successful delivery. Assistant message IDs identify complete exchanges. Late success can repair failed sends and invalidates summaries/campaigns/receipts that could have omitted the repaired turn; late failure cannot undo success.

Bounded version-1 `state_meta` records include:
- `oswald:v1:files:<session-id>`: first-writer-wins frozen USER/MEMORY pair. Both string fields are required; incomplete/corrupt snapshots fail closed.
- `oswald:v1:turn:<session-id>:<assistant-id>`: correlated user message ID, bounded native tool history, successful tool names, prompt pressure, delivery state, generated-image references.
- Profile summary/compression receipt/campaign keys: durable validated artifacts, source ranges, retries, exact leases, credits, and campaign high-water.

Native version-1 tool history permits an optional `result_name` on successful single-entry MCP bridge calls. `name` remains the assistant invocation (`tool_call`); `result_name` supplies the qualified remote name for the result transcript row, display, and text-only replay. Missing `result_name` retains the original name behavior. Batch results remain named `tool_call`. Existing records are not rewritten and the SQLite schema is unchanged. Provider wire copies align the result name to its correlated assistant invocation without changing stored content or identity.

`/new` is bookkeeping only: it ends the conversation's open session (`end_reason='new_session'`) and advances generation, leaving the transcript and metadata in place. The next turn opens a fresh session from zero and re-captures the current memory files; memory files are never changed by the command. Nothing eager-deletes prior sessions — they remain delivered and searchable until ordinary TTL expiry sweeps them (messages deleted, generation high-water kept). Supplied FTS triggers index inactive pending messages too; every search consumer joins canonical delivered state (`messages.active=1`) and never exposes pending rows. FTS alone never authorizes exposure.

SQLite uses foreign keys, secure delete, WAL, synchronous NORMAL, a five-second busy timeout, immediate transactions, and a 1,000-page automatic checkpoint. Maintenance runs immediately then hourly, selects at most 100 expired sessions and 100 timed-out pending exchanges per transaction, preserves generation bookkeeping, marks pending delivery failed after fifteen minutes, and separately performs a passive WAL checkpoint. Session inactivity is 24 hours. Counts reflect committed work only.

## Startup and Shutdown

`startup.Serve` loads configuration, prints the terminal-only bright-magenta UTF-8 banner, creates the logger, installs signal handling, and calls `startup.Run`; both `oswald start` and `oswald-server` use it. No stores/workers/gateways are assembled in `main` or `internal/cli`.

Startup validates the immutable directory, then initializes profiles in sorted order: approved state store, maintenance, file/soul/cache stores, builtin registry, model client, shared foreground/background compactor, lazy profile MCP manager/provider, agent, cache expiry worker. It then assembles the shared foreground broker, profile commands, low-priority compression workers, and configured gateways with profile-selected runtime dependencies.

Ordinary and partial-failure cleanup stop outbound delivery, cache/maintenance workers, broker, compression workers, MCP sessions, then databases. Workers join before stores close. Startup errors return only after cleanup. DEBUG `app.profile.initialized` reports safe profile ownership. INFO `app.stopped` reports acquired-resource cleanup, not listener readiness or a full websocket shutdown contract. Gateway start failures are asynchronous logs; listeners can outlive `Run` until process exit. This is not an in-process restart API.

## Agent, Memory, and Budget

The agent reads the current operator profile soul on each request, falling back to `.oswald/SOUL.md` without copying. Souls are regular safe files bounded to 1 MiB. Profile roots are existing private directories; reject symlinks and wrong ownership. No model tool edits policy.

On a conversation's first model turn, capture USER/MEMORY; subsequent turns read the frozen pair. New/fresh sessions capture latest files; restart alone does not reset state. File edits commit immediately, even if later model/storage/delivery work fails, and do not change the active session's frozen system prompt. Stateless API reads fresh once per request. Files are never populated from removed legacy facts.

The system message contains soul, complete nonempty MEMORY then USER PROFILE blocks, a server-local runtime block (conversation start, current date with a trust-over-start directive, model, provider key, platform), a trusted profile runtime-environment block (host, user home, current working directory, scratch directory with TMPDIR note), a Current Session Context block (containing untrusted metadata), and a final trusted per-platform notes block (capability limits and formatting guidance for Discord/iMessage). The runtime block is required context and is always rebuilt per request; stateless requests omit the conversation-start line. The session-context block is derived from gateway-supplied conversation labels and omitted when no label is set (stateless/API). Model-editable files have system-role influence by operator choice; text cannot grant server-side tool authorization. Summaries/tool history are explicitly untrusted lower-authority reference data. Current/replied images are not durably replayed. New stored user turns retain gateway reply enrichment (`[Replying to ...]`) with their incoming text through the shared agent path, including reply-only turns. Delivered history, search, and compression therefore retain what was being answered, subject to normal budgets and expiry; quoted text is not elevated to deployment instructions. Existing turns are not rewritten and previously stripped quotes cannot be recovered. No schema or persisted JSON-format changes are made. Reasoning is never persisted in conversation/tool history.

When image generation or vision analysis is registered, current attached/replied images carry `[Image attached at: <private cache path>]` annotations in the same user message as their text and image bytes, not a separate catalog message. New turns persist these annotations alongside reply enrichment in user transcript text so follow-up history retains the paths and quoted context without replaying image bytes. Existing history is not rewritten. Uncached images retain count-only annotations. Paths do not extend cache expiry and may become unavailable after 24 hours. Generated previews appear directly in their tool results; follow-ups use text-only tool history, with no separate session-image catalog message.

`USER.md` is limited to 1,375 Unicode runes; `MEMORY.md` to 2,200, including `\n§\n` separators. Entries must be nonempty UTF-8 and cannot contain a standalone separator line. Prompt blocks include complete contents, integer capacity percentage, and rune counts. Missing files are empty. Reads use atomic-replacement visibility but do not form one cross-file point-in-time snapshot.

`memory` requires the authenticated owner and exact target `user`/`memory`. Supply either one action or 1–20 ordered operations. Add requires content; replace requires unique-entry old text and content/new_text (`content` wins); remove requires old text only. Replace/remove select exactly one entry, not arbitrary substrings for partial writes. One batch is atomic for one target; stable private per-target flock files, re-read, validation, synced temporary file, rename, directory sync prevent competing-writer loss. No cross-file/SQLite/delivery transaction exists. External editors must follow the locks. Capacity errors return current entries for consolidation; success returns updated contents and counts. The description mentions `skill_manage`, which is not registered.

Budget defaults: 32,768 context, 256-token safety margin, no reserved output tokens, 70% compression trigger. Tools/images are estimated per actual request. Recent-tail allowance is 25% of usable input, bounded 2,000–8,000 and available input. Prefer up to two newest complete exchanges, then optional summary, then older complete exchanges. Never split an exchange or truncate required file context. Provider usage is telemetry, not pressure-policy input. Required oversize context is retained/logged; optional context omitted. Stateless API returns an `over_budget` response (gateway: `400` history-budget error) when required/current context cannot fit, and never compacts/truncates client history. Gateway-side history sizing is tokens-only: no per-message or aggregate character caps (transport body limit still bounds raw size); structural bounds on counts/IDs remain.

Tool authorization uses the exact iteration catalog; discovery cannot authorize another call in the same emitted batch. Execute serially and append a correlated result for every declared call, including blocked ones. Global limits are 50 actual handler executions and 30 model responses containing calls; final completion then uses tools disabled. Successful/unproductive fingerprints persist, execution errors release for exact retries. Zero per-tool limits disable only per-tool guards.

No overall generation deadline exists. All model calls use synchronous streaming, silent when no callback (iMessage/compaction). No `max_tokens` is sent. Cancellation interrupts provider work; upstream/provider/tool deadlines still apply. Recognized Ollama image resource failures allow five attempts per retry sequence with progressively fewer current images. Qwen parser failure retries the identical request once; empty visible output has a separate tools-disabled corrective call. Context failures may force transient foreground compression. Non-cancellation failures after successful image generation deliver deterministic partial text with selected images through ordinary pending/delivery gating; cancellation never publishes a completed turn. Image persistence failure prevents delivery. Ordinary nonimage append errors may log and still return an answer.

## Compression

Foreground compression checkpoints only validated complete tool rounds, uses current model-visible arguments/results, omits reasoning/attachment bytes, and retains old context on failure. Durable `compaction.ProfileService` runs after delivery and every 30 seconds behind the shared broker's foreground-priority gate.

Chunks contain at most 64 complete delivered exchanges and fit actual model input budget; pending delivery is a barrier. Version-1 campaigns pin a delivered high-water target across partial checkpoints. Retry ranges remain fixed if newer turns arrive. `compression_locks` use five-minute renewable exact tokens. Receipts retain four provider credits, corrective feedback, immutable artifacts, completion/dead state. Saved artifacts recover after restart without another credit; preemption refunds only before artifact save. Publication atomically validates exact live lease, complete delivered range and unchanged source text, then writes summary/completion. Oversized complete exchanges get dead receipts. Scope scans page by conversation key to avoid starvation.

The model uses silent synchronous streaming, temperature 0, no parallel calls, and one required `session_summary_save` call. Summaries contain narrative, tasks, commitments, entities, decisions, topics, ordered source IDs and covered range. Bounds: narrative 8,000 runes; arrays 50 items; items 1,000 runes; aggregate structured text 16,000 runes; encoded artifact 40,000 bytes. The nested `candidates` wire field remains in version-1 artifacts but active compression requires it empty. No fact extraction/publication exists. Summaries never delete covered transcript or publish notes.

## MCP and Tools

Operators configure `mcp_servers.<name>` with exactly one of `url` (HTTP) or `command` (stdio). HTTP entries take an `http`/`https` URL, optional `transport` (`streamable_http` default, or `sse`), headers, and tool filters; stdio entries take `command` plus optional `args` (≤32 × ≤4096 chars), `cwd` (relative resolved against the profile root without `..` escape, absolute allowed), and `env`. Both take optional `tools.include`/`tools.exclude` remote-name lists (empty include allows all, exclude wins) and `enabled` (default true). HTTP Streamable servers may set `auth: oauth` with an `oauth` block (`client_id`/`client_secret` optional, `flow: browser` default or `device`, `scopes`, `timeout` 30s–30m default 5m); OAuth owns the `Authorization` header (a static one alongside is rejected) and is refused for SSE/stdio. Names: 2–40 lowercase ASCII characters starting with a letter; `soul` reserved. At most 32 servers/32 headers/32 env entries, map values at most 8,192 bytes, no newline/NUL. Restart reloads configuration. Inherited servers become independent profile-owned connections/credentials; no runtime global administration or encryption key.

Sessions connect lazily during bridge search/describe/call catalog builds and execution, never at startup. No per-server discovery tools or direct deferred tools are advertised and no recent-turn pre-exposure exists: the model sees exactly the `tool_search`, `tool_describe`, and `tool_call` bridge. Deferred tools are named `mcp__<server>__<remote>` and execute only through `tool_call` against the live profile-scoped catalog; direct deferred calls are unadvertised and blocked, and legacy dot-qualified names never resolve. `tool_search` takes 1–7 keyword queries plus an optional per-query limit (default 5, clamped 1–25) and requires every query word to appear in tool text; empty hits return available sources plus a retry hint instead of claiming the capability is missing. `tool_describe` takes 1–10 deduplicated names and reports schemas, `not_found`, and `errors` (bridge/eager names must be called directly). `tool_call` takes 1–10 `{name, arguments}` entries, validates required arguments, executes serially in input order, and rejects bridge self-invocation and out-of-scope names. The `tool_search` description carries the live deferred-tool count and embeds a listing when it fits 1,500 runes. Bridge/search/describe/call flattened envelopes are bounded to 16,000 runes after receipt, not a body cap. Read/write remote tools are eligible; remote `tools` reserved; qualified names fit 64 bytes. Projection supports compatible top-level object parameters, required flags, bounded descriptions, safe string enums, not full nested JSON Schema. HTTP and initial connection each have separate 30-second bounds. Shutdown closes sessions and fences late cache publication.

MCP network validation rejects userinfo and unresolvable hosts at setup, and bounds the SSE handshake (10s dial/TLS, 30s response headers); the SSE stream itself lives until session close. OAuth discovers via protected-resource metadata with a same-origin fallback, tries operator credentials, then CIMD loopback, then DCR (refusal marker `.cimd-off`), and binds tokens to the discovery issuer. Tokens/clients/metadata persist as 0600 files under `<profile>/mcp-tokens/` (0700); the service refreshes lazily and fails closed into a re-login prompt, while `oswald mcp auth <server>` (browser with loopback callback/paste-back, or RFC 8628 device flow) is the only interactive path. It does NOT implement validated-IP dialing, proxy exclusion, redirect revalidation, or private-range filtering — local HTTP endpoints are operator configuration, and stdio commands run with operator trust. Endpoints/catalogs/commands/credentials are trusted operator configuration, not a comprehensive SSRF/RCE boundary.

Builtin inventory: `memory` always (metadata history, no per-tool guards); `session_search` always when a profile store is present (full searchable history, unproductive limit 2, `BlockDuplicates`), returning delivered messages from the authenticated owner's profile excluding the live session and the sessions forked from it (older lineage generations predate the live conversation and remain recallable, deduped to one entry per lineage root), plus read-only group-scoped peer history: discovery fans out to peer profiles constrained to the live group conversation's source plus channel/chat id (DMs never match), and `profile` with `session_id` resolves a cross-profile `@session:<profile>/<id>` link only when the target session shares that same group; `web_search` when Brave/SearXNG configured (full history, failure/unproductive limits 2/2); `image_generate` when ComfyUI configured, hidden for the API (full nonsearchable text history, no per-tool guards); `vision_analyze` always, independent of ComfyUI (full nonsearchable text history, failure limit 2, `BlockDuplicates`); workspace tools `read_file`, `write_file`, `patch`, `search_files`, `terminal`, `execute_code` always (full searchable history, `BlockDuplicates`; `read_file`/`search_files` unproductive limit 2, all six failure limit 2). `terminal` foreground runs bounded capture with infra retries; `background=true` spawns tracked (`session_id`, `persist_on_release`, over-cap foreground promotion) polled via `process_manage` (`list|poll|log|wait|kill|write|submit|close|handoff`, prefix match, handoff cap 3, 7d/newest-64 retention). `cronjob_manage` (`create|list|update|pause|resume|remove|run`) owns schedules, self-contained prompts, scripts with stdout injection, monitor diff gates with first-tick baseline, delivery targets (`local|all|origin|bot-chat[:profile]|platform:chat[:thread]`), and zero-tool `enabled_toolsets:[]`; update order core->script->context->run, first failure wins. Pre-execution chain (force cannot bypass lifecycle): supervised-gateway lifecycle scan (referenced scripts ≤1MiB/NUL-checked, unscannable fails closed), workdir allowlist, self-repo git-mutation block, foreground detachment refusal with `background=true` rewrite hint, destructive-pattern detection blocked pending operator approval. Backends: local `/bin/sh -c` only; docker/ssh/cloud-sandbox/plugin are not configured in this deployment. Workspace file paths resolve inside the profile working directory only (`default` = profile root, named = `profiles/<name>/`); `../`/absolute/symlink escapes and operator secrets (`config.yaml`, `.env`, `state.db*`, `mcp-tokens/`, `memories/`, `SOUL.md`, plus `profiles/*` for `default`) fail closed. `write_file` requires a current full `read_file`/`write_file` in the same request and refuses on external modification; `terminal` runs foreground `/bin/sh -c` with a minimal environment and `TMPDIR=<cwd>/cache/scratch/`; `execute_code` runs stateless `python3` per call with no cross-call kernel state. Never log workspace paths, contents, queries, or command output. Native history has 16 KiB arguments/16,000 result-rune per-call bounds and 64 KiB aggregate encoded trace bound. Builtin definitions and ComfyUI graphs are compiled Go, not runtime JSON files.

New image tool calls retain prompts/questions, source paths/URLs, crop arguments and readable result text in the existing version-1 tool trace, but never image bytes or reasoning. Inline data URL arguments are replaced with `[Inline image data omitted]`. Follow-ups replay correlated assistant calls and text-only tool results. Generation results replay their original text without an added historical prefix; vision results retain an explicit historical annotation. Replayable image pairs survive another tool's metadata-only/unavailable history and do not require the image tool to remain configured; normal context/history budgets still apply. Old metadata-only traces cannot recover discarded text. Image tool text is not included in the tool-history search projection, and gateway tool previews remain suppressed.

`session_search` exposes stored messages with no model summarization or embeddings. Four shapes are inferred from arguments: `query` (discovery, FTS5, deduplicated by session lineage, BM25 ranked with optional gentle newest/oldest relevance bias, adaptive top-result hydration), `session_id` + `around_message_id` (scroll window, clamped 1–20 each side), `session_id` alone (all delivered rows up to 30, otherwise first 20/last 10), and no arguments (recent delivered sessions, default three; `limit` also applies to browsing). Discovery uses a disposable in-memory SQLite FTS5 projection of eligible message content, titles, and native tool search text, not a new persisted index. Default match roles are user/assistant; `role_filter` may include tool search text, but never filters surrounding context. Title matches are eligible with user/assistant roles. Time bounds apply to session start time before ranking. Exclusions and lineage deduplication cannot consume the result limit. Only Discord/iMessage sessions are discovered/browsed; no scheduled/internal worker session taxonomy is provisioned by this application.

Every source read joins `messages.active=1` so pending rows never surface even though the supplied FTS triggers index them; generation equality is intentionally not required, because `/new` leaves prior sessions as searchable history. Reads are scoped to the authenticated owner's profile and fail closed across profiles. The live session and its forks remain excluded from discovery/browse and rejected for scroll/read; older lineage generations stay searchable as delivered history. A concrete child session is read directly, never redirected to its parent; windows and anchors are restricted to that same session. Expanded discovery includes five messages each side and three-message bookends; lower adaptive results include the match only. Remainder counts describe delivered messages outside the returned window. Native traces are returned text-only in `tool_history` on their owning assistant message, with canonical message ids for scrolling rather than invented tool-row ids; calls/results remain paired. Tool-result matching honors stored `SearchResult` policy, so image-tool text stays nonsearchable. Message content is rune-capped (4000 window, 2000 read/compact match, 1200 bookend), native trace results at 1000 runes/call and arguments at 1200 runes/call, with truncation flags; at most 50 trace calls are exposed per owning message. Whole envelopes stay within 14,000 runes, progressively reducing optional context/text while preserving navigation and marking truncation. No reasoning/image bytes or new persisted fields are introduced. `link` values are `@session:<owner>/<id>`, written verbatim by the model. Never log query text or message content.

Web search: query 400 runes/50 words; provider bodies 2 MiB; normalize first 50 candidates into at most 50, two per hostname, 16 KiB complete model envelope. Optional integer limit 1–100, default five, is an upper bound, not a promise. Strip tracking/fragments/duplicates; result destinations are untrusted. Wrapper is `<untrusted_tool_result source="web_search">` with warning and escaped JSON exactly `success:true,data.web`; entries contain title/url/description/1-based position only. Empty web is `[]`; degradation is status/telemetry, not extra JSON fields.

Brave: POST LLM context endpoint, version `2026-07-31`, US English, spellcheck, SafeSearch off, balanced, eight URLs, approximate 3,072-token budget, 50 attempts/rolling second, 30-second attempt timeout, no redirects. Retry once for explicit 408, eligible short-window 429, selected 5xx; never retry ambiguous metered transport/malformed successes. SearXNG: configured base plus `/search`, first-page JSON general/en-US, eight-second attempts, one retry, same-origin redirects; private deployment addresses allowed. Brave primary, SearXNG fallback on failure/no usable results; clean empty fallback is not degraded. Never log queries, URLs, bodies, headers, credentials.

OAuth discovery accepts operator-trusted HTTP and HTTPS endpoints, including LAN IPs and local hostnames; HTTPS certificate verification remains enabled. HTTP transmits codes and tokens without transport encryption, so HTTPS is recommended. All OAuth metadata/registration/token HTTP sends a product `oswald-ai/` User-Agent. Discovery documents are capped at 64 KiB with 30-second HTTP bounds; issuer comparison normalizes a trailing slash, and an origin-issued document is accepted for a same-origin path-scoped advertised issuer (the advertised identifier stays bound to the credential) while all other mismatches fail closed. S256 PKCE is required when a browser authorization endpoint advertises challenge methods without S256 (the error names the advertised methods); servers that omit the list are tried. Metadata with an empty or `+json`-suffixed content type is tried; other content types fail closed naming the type. Only absent metadata (404/410) permits discovery fallback; malformed documents, identity mismatches, and network/server failures fail closed. Device endpoints are parsed from the same authorization-server document. DCR registers a native client with grant/response types and `token_endpoint_auth_method: none`; a secret issued without a method is sent in the body. Re-login reuses the cached registration redirect URI instead of registering per ephemeral port, and changing the configured operator client drops stale tokens. The browser callback ignores query-less follow-ups, takes the first terminal result, checks exact state and an advertised `iss`, and offers paste-back plus a skip path whenever stdin is present. Refresh POSTs the resource indicator under a cross-process fence (30s bound, never POSTs unowned), adopts a peer-rotated pair instead of spending a burned grant, carries forward omitted refresh/scope values, and discards dead dynamic registrations (operator clients never auto-heal); concurrent 401/403s on a rotated token dedupe into one recovery. An omitted scope is omitted on the wire (DCR omitempty, no authorize/device/refresh scope field; the server grants its default set) and the token response's scope is authoritative for persistence. Request scopes are selected automatically with an exact priority: explicit oauth.scopes verbatim, else the live 401/403 WWW-Authenticate challenge scope, else PRM scopes_supported in advertised order, else AS scopes_supported in advertised order, else omitted; offline_access is appended (no duplicates) when a scope was selected, the AS advertises offline_access, and the grant list contains refresh_token. The service never starts interactive flows: a later insufficient_scope challenge naming scopes beyond the stored grant fails closed into a re-login prompt, and the next `oswald mcp auth` run requests the union (stored order first, new values appended) after re-harvesting the live challenge; the harvested resource_metadata URL is preferred as the first discovery candidate. Scope values are never logged (sources/counts only). This does not add private-network filtering or change persisted OAuth files.

Protected-resource identifiers may be the exact configured MCP endpoint or a same-origin base covering it at a path-segment boundary (for example Home Assistant's origin-level resource). Foreign origins, sibling paths, and dot-segment paths fail closed. Interactive authorization and token requests use the advertised resource identifier; it remains request-local and is not added to persisted metadata/token JSON.

Bridge discovery (`tool_search`/`tool_describe`) returns plain JSON without the former `type`/`untrusted`/`notice`/`data` envelope or XML wrapping; remote descriptions/schemas remain untrusted data despite local assembly. Successful single-entry `tool_call` returns the remote result text directly under its qualified result name. Remote result text of at least 32 Unicode characters is enclosed in `<untrusted_tool_result source="mcp__…">` with a fixed external-data warning; shorter results intentionally remain unwrapped. Delimiter-like text is escaped. Batches return one plain JSON `results` array in input order with qualified names and individually framed remote contents; locally generated errors remain unwrapped. Complete framing counts toward the 16,000-rune limit and is retained during truncation, or external content is explicitly omitted if framing cannot fit. Oversized describe results omit complete schemas with explicit per-tool errors instead of advertising partial schemas.

## Images and ComfyUI

`vision_analyze` requires `image_url` and a nonblank question of at most 2,000 runes, with optional four-integer `region`; unknown fields are rejected. Sources are public HTTP/HTTPS URLs, the authenticated profile's unexpired managed cache paths, or base64 PNG/JPEG/GIF/WebP data URLs. Other local/other-profile files are rejected. Downloads are read-only with pinned public-IP dialing, no proxy, a 20-second bound, redirect revalidation and no HTTPS downgrade. Source bytes are capped at 8 MiB, each dimension at 8192, and decoded pixels at 32 million before decoding. GIF uses only the first frame. Crops use source (cached-image) coordinates with exclusive x2/y2, are validated within bounds, and happen before model normalization (2560 longest edge/280 KiB); cached attachment detail lost at initial normalization cannot be recovered. Readable loading confirmation, question, source dimensions and one request-local image are sent directly in the correlated tool result as text/image content parts, not a separate user message, analysis-model call, or outbound attachment. This requires upstream support for multimodal tool results. Cropping/downscaling notes map displayed coordinates back to the cached source using independent x/y scales and crop offsets; retry notes are rebuilt for the actual dimensions sent on each attempt. Unchanged full images have no geometry note; GIFs identify first-frame loading. The latest four loaded images survive compaction/retries alongside up to four current and four generated images; compaction retains complete correlated assistant/tool batches containing active vision inputs. Loaded bytes/crops and request-local geometry are not cached or persisted; inline data URL bytes are omitted from foreground compaction debt and retained tool-call arguments. Durable history retains text only as described above; gateway tool previews remain suppressed. Ordinary `tool.completed` owns execution monitoring.

`image_generate` exposes only required prompt, optional landscape/square/portrait ratio, optional `image_url`. Prompt nonblank, ≤2,000 runes, no unknown fields. Omitted source means text generation, never implicit edit. Source must be public HTTPS or an authenticated owner's unexpired cache path; arbitrary local/other-profile files rejected. HTTPS imports have pinned public-IP dialing, no proxy, bounded size/time and redirect revalidation. A successful result contains readable confirmation, the absolute private cache path, source dimensions and a normalized image preview directly in the correlated tool message, not a public URL/internal identity/version or a separate user message. Generated previews use the same bounded still-image normalization as `vision_analyze` (first frame for GIF), with geometry notes refreshed to actual dimensions during retries. The original generated bytes, not the model preview, remain cached and are selected for delivery. Previews and geometry remain request-local; durable history retains text only as described above, and gateway tool previews remain suppressed. Upstream multimodal tool-result support is required.

At most four latest generated previews and four latest `vision_analyze` inputs remain attached to their tool results after each tool batch, alongside up to four current user images. Foreground compaction retains complete correlated assistant/tool batches containing active image inputs. No separate user/catalog message is injected for current or prior generated images. Internal editable catalog bound 24; selected deliverables pinned. Final delivery chooses latest successful version of each logical image produced this request in first-production order. Fifth logical deliverable is rejected before provider submission; edits remain allowed. Failed edits preserve prior successes. Stable cache selectors retain logical identity/high-water across turns; counters reserve before provider work and may leave gaps. Persist selected outputs in generation order, independently of delivery order.

State stores at most four image references/exchange and eight/session, including pending. Only delivered active-generation unexpired references load. Cache files expire after 24 hours; missing/expired files cannot be reconstructed from SQLite. Image bytes are not BLOBs, history, summaries, or FTS. Reads normalize cache originals to bounded model inputs. Session expiry removes metadata; files may survive until private cache expiry. Cache worker runs immediately then hourly, only matching regular files, joins before shutdown. Operator backups and ComfyUI storage are outside deletion boundary.

ComfyUI graphs: SD3.5 Large Turbo, GGUF UNet `sd3.5_large_turbo-Q5_0.gguf`, dual CLIP `clip_l.safetensors`/`t5-v1_1-xxl-encoder-Q5_K_M.gguf`, VAE `diffusion_pytorch_model.safetensors`. ModelSamplingSD3 shift 3, euler/sgm_uniform, four steps, CFG 1, batch one, fresh seed, empty negative prompt. Landscape 1280×720, square 1024², portrait 720×1280. Image edits Lanczos/center crop, default denoise .75; transformations do not guarantee localized preservation. Dedicated serialized instance required: `/free` globally unloads models. Generation timeout starts after caller-cancelable permit acquisition; detached cleanup has ten-second bound. Output PNG/JPEG/GIF/WebP ≤8 MiB, dimensions ≤8192, MIME/DecodeConfig validated.

## Gateways

Discord/iMessage accept current images; the API gateway returns text only. Private messages need no mention by default. Ordinary group messages and group commands require configured mention policy or a recognized bot reply. A mention must be the first thing the sender says (leading whitespace trimmed): Discord checks leading native `<@ID>`/`<@!ID>` tokens, while BlueBubbles uses `mention_pattern` regexes anchored at the start (default `@?Oswald\b`); a matched leading mention is stripped before the model call. `require_mention` (default true) gates group/guild invocation only. Transport scope/reply context does not alter sender ownership. Commands receive authenticated profiles; no administration role. `/stop` cancels current active conversation work, preserves queued prompts; `/stop all` rejected.

Sessions: Discord DM `discord:dm:<author>` or group `discord:<channel>:<author>`; iMessage DM `imessage:dm:<sender>` or group `imessage:<chat>:<sender>`. Each gateway derives an untrusted conversation label for the system prompt: DMs use `"DM with <display name>"`; Discord groups fetch the channel/guild name (`GET /channels/{id}`, `GET /guilds/{id}`) and iMessage groups fetch the chat name (`GET /api/v1/chat/{guid}`), cached one hour and degrading to `"group channel"`/`"group chat"` on failure. Fetches run after preflight admission, log only status/HTTP code (never names or IDs), and names are sanitized and bounded before rendering. Broker lanes use profile/conversation with a fixed single worker and outstanding capacity ten plus that worker; the upstream model backend owns request queuing. Scheduled commands drain independently on shutdown; agent work is lifecycle-cancelable. Foreground work preempts low-priority compression.

Discord streams status/previews under its 2,000-unit limit; final inventory reconciles streamed output. Final answers/errors/fallbacks/commands share one FIFO outbound worker, 20 entries/80 MiB, each five-minute admission deadline and 15-second attempts. Transient network/408/429/5xx retries exponential 1–30 seconds; numeric Retry-After can exceed cap but not deadline. Stable nonce/enforce_nonce and chunk/attachment progress provide best-effort duplicate suppression, not exactly once. Missing-message 404 allows replacement; transient edits never delete/replace. Shutdown joins outbound before broker drain. Partial delivery is not rolled back; runtime marks success/failure. Tool chunk attachments are ignored.

iMessage authenticates BlueBubbles password through supported query/header fields; DM admission precedes reply/media/indicators. The webhook route is operator-configurable via `webhook_path` (default `/bluebubbles/webhook`). Sends typing/read indicators and final-only response with existing plain-send fallback. Reply resolution has shared five-second deadline, 1 MiB REST caps, exact GUID/chat checks, two-row bounds, no pagination. Group threads use the newest conversational message strictly before the incoming reply in the same chat/thread for both admission and quoted context, including the root when no earlier reply exists. Neither cached/root authorship nor webhook/REST `replyToGuid` associations override that chronological decision. An unmentioned group reply, prompt or command, invokes only when that predecessor is an eligible bot message; mentioned group messages use the same predecessor for enrichment. The prompt quotes its complete text as `[Replying to Oswald: "..."]` without a predecessor qualifier. Nonthreaded/DM references retain direct resolution. Creation-date/ROWID order, thread parts (tolerating an omitted part on either side), corruption/retraction, errors, and intervening humans are checked. Failed thread lookups expose no fallback root context. This is chronological continuation, not exact UI target proof.

API: configurable `api_host` (`127.0.0.1` default, `0.0.0.0` opt-in LAN) listener that always requires a per-profile bearer key. Listener address/port are global shared settings; each profile sets its own key via overridable top-level `api.key` (fixed `OPENAI_API_KEY` var resolved from that profile's merged `.env`, empty disables API access for the profile). Startup fails on duplicate key material; missing/bad keys are indistinguishable `401`s with `WWW-Authenticate: Bearer` and never log secrets. The presented key selects the owning profile, so tools/memory/soul/MCP stay profile-scoped with no cross-profile joins. GET `/v1/models` lists `oswald` and `GET /v1/models/oswald` retrieves it, both as spec-pure objects (`id`, `object`, `created`, `owned_by`) with no additive discovery fields; clients declare capabilities and limits locally. POST `/v1/chat/completions` is stateless and stores no turns/snapshots/summaries/images. Client history (user/assistant/system/developer/tool, assistant `tool_calls`, prior `reasoning_content` (≤128 KiB) retained as quoted reference) is lower-authority quoted reference, never replayed as deployment roles; optional participant `name` fields (`A-Za-z0-9_-`, ≤64 chars, never on `tool` messages) are retained as history metadata, with the current-turn sender always the API key owner. Caller `tools` (≤64 function definitions, ≤64 KiB each, object parameters) are the default catalog; Oswald builtins are opt-in only via `named` or `allowed_tools`, with Oswald names winning on collision. Tool names accept a compatible superset of the spec charset (`A-Za-z0-9_.-`, ≤128 chars) so deployed OpenAI-compatible clients keep working; strict spec names always validate. `tool_choice: none` offers no tools at all. Oswald-owned calls execute internally with a bounded `oswald_tool_calls` details timeline (live SSE deltas plus buffered message field, ≤32 entries, result text ≤4000 runes); caller-owned calls return verbatim with `finish_reason: tool_calls` (`content: null` when answer-empty) for the external app to run and post back as `tool` messages — the standard round-trip. `tool_choice` `auto`/`required`/`named`/`allowed_tools` accepted; `auto` offers only caller tools, `required` needs a nonempty caller catalog, unknown named/allowed names are rejected, `named` offers exactly that tool (builtin or caller) while `allowed_tools` (`mode` `auto`/`required`, 1–64 `function` entries) intersects the merged Oswald and caller catalog. Forcing (`required`/`named`/`allowed_tools` with `mode` `required`) is enforced on the first provider call only; single-tool forcing disables parallel calls unless the caller overrides `parallel_tool_calls`, which is otherwise honored. Strict JSON, application/json (charset suffix allowed), model oswald, 1+ messages ending in a user turn (new prompt, text/image) or a tool turn (standard tool-result continuation, driven by a fixed neutral prompt); text-only string/≤32 text parts, plus standard `image_url` parts (data URLs and http/https, ≤4, normalized ≤2560px/280KiB) on the current user turn only. History sizing is enforced in tokens against the caller profile's model budget only (no character caps); over-budget stateless turns return `400` context-budget errors, never truncated answers. Prior reasoning ≤128 KiB retained as quoted reference, never replayed as model reasoning or persisted. Client max_tokens/max_completion_tokens set a per-provider-call completion cap (nonpositive rejected, `max_tokens` winning when both are present); sampling parameters `temperature` (0–2), `top_p` (0–1), `frequency_penalty`/`presence_penalty` (−2–2), integer `seed`, and `stop` (string or ≤4 sequences) are validated and passed to every stateless provider call, and `parallel_tool_calls` is honored; `n` must be omitted or 1. Remaining hints (`top_k`, `repetition_penalty`, `user`, `logit_bias`, `logprobs`, `top_logprobs`, `reasoning_effort`, `store`) accepted and ignored; validated `service_tier` values are echoed in completion responses (single-tier deployment, no routing change); `response_format` accepts `text`/`json_object` (`json_schema` rejected); legacy `function` role/messages are rejected; every error carries `param` alongside `type`/`code`; unknown top-level fields and trailing JSON rejected. SSE streams actual thinking as reasoning_content, progressive content deltas, server-side `oswald_tool_calls` timeline deltas, and caller-owned tool_calls deltas, then finish (`stop`, `length`, `content_filter`, or `tool_calls`)/`[DONE]`; buffered responses carry `reasoning_content` and `oswald_tool_calls` alongside content and the same terminal `finish_reason`. `usage` carries observed provider-reported request totals whenever at least one call reported (omitted otherwise, never invented); streamed only with `stream_options.include_usage`, as a final choiceless chunk before `[DONE]`. Validation failure is pre-runtime; a disabled or unconfigured listener is unavailable, not automatic provisioning. Client disconnect cancels in-flight stateless work via the transported request context (`request_canceled`, lane released, queued prompts untouched); commands deliberately outlive transport cancellation. Commands are not supported on the API: a final message starting with `/` is rejected pre-runtime as `400` `invalid_prompt`, and a command that reaches the responder fails with `400`.

Media: four current images, 10 MiB each, JPEG/PNG/GIF/WebP/HEIC/HEIF; normalize ≤2560 longest edge/280 KiB JPEG/PNG before base64. GIF contact sheets; Discord GIFV ≤10 MiB/20 seconds/up to four ffmpeg frames with preview fallback. Output attachments ≤8 MiB each/ten files/80 MiB aggregate, safe unique basenames ≤255 bytes. Final model text may carry MEDIA:/absolute/path tokens resolved at finalization against the sender's unexpired managed image cache (ownership/expiry/MIME enforced, foreign or arbitrary paths stripped text-only); tokens never persist into history and are stripped for the text-only API. Source decoding precedes resize and full GIF animation decode; these limits do not guarantee strict peak decoded-memory/frame bounds. No general files/audio/arbitrary video input.

Still-image normalization applies declared display orientation before resizing/encoding: all eight EXIF orientations (rotation and reflection) for JPEG and EXIF-bearing PNG/WebP, and ordered primary-item `irot`/`imir` transformations for HEIC/HEIF. HEIF container transformations are authoritative, not compounded with camera EXIF. Missing/malformed optional EXIF leaves pixels unchanged; orientation is never inferred from visual content. Attachment cache bytes already contain the corrected pixels and no orientation tag, so cached reads/retries cannot rotate them twice. Vision/generation previews use the same correction, with source dimensions and crop coordinates in the oriented display frame, before further downscaling; original generated delivery bytes remain unchanged. Existing normalized cache files without retained orientation metadata cannot be automatically repaired. No schema or persisted image-reference format changes are made.

## Monitoring and Security

INFO is a compact activity/lifecycle stream: exactly `app.started`, `app.stopped`, `gateway.connected`, `chat.requested`, `chat.completed`, `command.completed`, `tool.completed`, `tool.blocked`, `compaction.profile.started`, and `compaction.profile.complete`. DEBUG is development telemetry (provider accounting, queues, loading, persistence, attachments, compression, maintenance, MCP, and retry detail). WARN reports recoverable failures/degradation; ERROR is reserved for startup failures, stopped critical gateways, and failures preventing safe operation. Cancellation, empty results, routine ignored/rejected input, and normal tool governance are not automatically warnings. Fixed developer-owned events/messages; literal reviewed field keys; counts/units numeric; safe bounded labels. Never log prompts, answers, reasoning, tool payloads, URLs, transport identities, session/chat keys, images, credentials, dotenv contents, or raw errors. Canonical internal `profile` names and generated request/operation correlation are allowed; `user_id` is an untrusted, sanitized gateway display label, never an ownership or join key. Use `config.ErrorField` for fixed codes; `SafeErrorText` is for user responses only. DEBUG has identical safety requirements.

Production stderr is single-line JSON; stdout banner is not a log stream. Logs are unversioned and share one universal envelope `ts, level, event, component, log_type, details`, where `details` carries `msg` plus every event-specific field, including correlation. Within `details`, correlation leads (msg, profile, user_id, gateway, request_id, operation/job, model), followed by alphabetically sorted operation fields, outcomes, sorted timings, and error_code last. The `service`, `instance_id`, and `record_kind` envelope fields are no longer emitted. Absent fields are omitted. log_type server/agent. String labels ≤256 UTF-8 bytes, messages ≤1024 bytes, records ≤16 KiB, scalar lists ≤16. Unknown/private string keys omitted; unsupported/nonfinite fields produce safe marshal-failure diagnostics. Output filtering is not a secret detector; source-value review remains mandatory.

`chat.requested` records authenticated, addressed chat turns before broker admission/model work; queue rejection therefore still has a requested/completed pair. Commands, fallbacks, ignored input, pre-runtime rejects, and background compression are excluded. `input_type` is text/text_image/image, derived from sender text and selected current/replied images before synthetic annotations/fallback text. `chat.completed` reports duration_ms, tool_count, and input_tokens/output_tokens (post-hoc; completeness is qualified by is_execution_complete and usage flags). Failed completions also carry error_code. execution_outcome, delivery_outcome, and is_execution_complete are omitted on success and appear only when non-ok/incomplete. Commands have only `command.completed`; actual handlers emit `tool.completed` with tool_name/outcome/duration_ms, and governance emits `tool.blocked` with reason_code, never an execution. Correlate by request_id; do not add requested/completed or chat/tool/diagnostic counts together. Missing completion may mean still running or interrupted. `app.started` means composition completed, not listener readiness; `app.stopped` includes partial-start cleanup, not a complete websocket shutdown guarantee. `gateway.connected` is emitted for Discord only after observed READY/RESUMED, for BlueBubbles after the webhook listener binds (reporting the capability-probe result), and for the OpenAI API after its HTTP listener binds (reporting listen address and port); it is never emitted before HTTP listeners bind.

Use `log.Server(component)` for infrastructure and `log.Agent(component, requestID, profileName, gateway, model)` for request agent work. Propagate `requestctx.LogFields` and operation/job correlation without fabricating unavailable transport metadata. IDs `_id`, counts `_count`, durations `_ms`, text sizes `_chars`, booleans `is_`. Success carries no `status` field (it is the implicit default); only error/rejected/retry/degraded are emitted. Canceled is outcome, not automatically error.

- DEBUG `provider.gateway.chat.complete`/`.embed.complete`: one invocation meter, including errors/cancellation. is_submitted means submission attempted, not successful remote completion. Async status polls are not extra submissions. Log only observed valid nonnegative usage; reported is not complete; missing fields never invented. Complete requires success and all required numeric counts. Duration is full wall time; effective_output_tps divides completion tokens by it; first output only for observed thinking/content. Retained explicit embedding/async client APIs are not live indexing paths.
- DEBUG `gateway.request.received` and `.complete`: detailed runtime operation and addressed terminal delivery summary. Pre-runtime rejects are separate diagnostics. Completion separates execution/delivery/persistence, timings, tool/model totals, reported/complete flags. Stop can return before provider completes; `is_execution_complete=false` and incomplete totals are honest.
- DEBUG `broker.request.execution.complete`: actual processor return, eventual execution totals, not delivery or complete remote billing. Never add provider, request, and execution aggregates together.
- DEBUG `agent.response.complete`: generation outcome; INFO `tool.completed`/`tool.blocked` own execution/governance activity. Provider/tool diagnostics are not extra executions.
- `agent.memory.files.loaded`/load_failed/bind_failed: safe counts and frozen/fresh state, never file contents. `agent.tool.web.search.complete`: requested/returned counts, invocation flag, duration/outcome, never query/results.
- `gateway.reply_lookup.complete`: safe bounded phase/reason/cache/remote/direct/predecessor counts, no identifiers or text. Logical remote operations are not HTTP attempts.
- No periodic health/gauge snapshots are emitted at any level. Broker queue state is observable through admission/rejection diagnostics and shutdown events; compression receipt health through per-attempt, scan-failure, and release-failure records. Maintenance/cache sweeps report safe committed counts and cancellation without invented successful zeros.
- DEBUG `mcp.profile.configured`: owner/server count only; no endpoints/headers. DEBUG `app.profile.initialized` and INFO `app.stopped`: resource lifecycle, not readiness. Routine file/reply/web/sweep measurements above are DEBUG; maintenance errors are WARN.

Test emission counts, INFO levels, scalar types, correlation, partial/negative usage, nil-response errors, late cancellation, rollback, and private canaries. The logging AST guard is limited, not proof of safe values. Loki labels should stay low-cardinality (level/log_type/component/event/optional gateway); parse profile/user/request/job/model/tool fields from the details object at query time. Absence of a periodic health record is not proof of zero activity; logs cannot recover unreported usage, lost records, or exactly-once ingestion.

Use SQLite online backup or stop before copying database plus WAL/SHM; a live main-file-only copy is unsafe. Restore while stopped and check integrity/foreign keys. The image includes ffmpeg and SQLite tools.

For tools: add group-owned definition/handler/policy, register composition, authenticate profile ownership from context, test advertised schema/governance/cancellation/output bounds, update inventory.
